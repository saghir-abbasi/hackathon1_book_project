# Implementation Plan: Chatbot UI Shell in Docusaurus

**Branch**: `004-chatbot-ui-shell` | **Date**: 2025-12-01 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/004-chatbot-ui-shell/spec.md`

## Summary

This plan details the implementation of a front-end only Chatbot UI Shell within the Docusaurus-based book website. The technical approach is to build a set of reusable React components, styled with CSS Modules to match a specific robotics theme. State will be managed locally within the components using React hooks (`useState`, `useContext`). All animations will be handled with lightweight, native CSS Transitions to ensure performance and avoid new dependencies.

## Technical Context

**Language/Version**: TypeScript (from `tsconfig.json` in Docusaurus project)
**Primary Dependencies**: React, Docusaurus
**State Management**: React Hooks (`useState`, `useContext`)
**Styling**: CSS Modules (`.module.css`), native CSS variables
**Animation**: CSS Transitions
**Testing**: Manual testing based on user scenarios in `spec.md`.
**Target Platform**: Web (Desktop, Tablet, Mobile)
**Project Type**: Web Application (Docusaurus)
**Constraints**: Must not interfere with existing Docusaurus theme. Must be globally available on all pages.

## Phased Implementation Plan

### Phase 1: Scaffolding & Environment Setup

**Goal**: Create the file and directory structure for the chatbot components.

1.  **Create Directories**:
    -   `docusaurus-book-site/src/components/chatbot/`
    -   `docusaurus-book-site/src/components/chatbot/components/`
2.  **Create Placeholder Files**:
    -   `chatbot/index.tsx`
    -   `chatbot/ChatbotButton.tsx`
    -   `chatbot/ChatWindow.tsx`
    -   `chatbot/components/ChatMessage.tsx`
    -   `chatbot/components/ChatInput.tsx`
    -   `chatbot/chatbot.module.css`

### Phase 2: Component Implementation

**Goal**: Build the static JSX and structure for each React component.

1.  **`ChatbotButton.tsx`**: Implement a button with a robot/chat icon. It will accept an `onClick` prop.
2.  **`ChatMessage.tsx`**: Implement a component that displays a single message, applying different styles based on whether the `sender` is `'user'` or `'bot'`.
3.  **`ChatInput.tsx`**: Implement a form with a text `input` and a `button` for sending messages. It will accept an `onSend` prop.
4.  **`ChatWindow.tsx`**: Assemble the layout.
    -   Header with the title "AI Assistant" and a close button.
    -   A container `div` for displaying messages (will be mapped from state later).
    -   Render the `ChatInput` component at the bottom.
5.  **`index.tsx` (Chatbot Container)**:
    -   Render the `ChatbotButton`.
    -   Conditionally render the `ChatWindow` based on an `isOpen` state.

### Phase 3: Styling & Robotics Theme

**Goal**: Apply the visual theme using CSS Modules.

1.  **Define CSS Variables**: In `chatbot.module.css`, define the color palette, fonts, and other theme variables.
    -   `--neon-cyan`, `--electric-blue`, `--circuit-border-color`, etc.
    -   `--font-heading: 'Orbitron'`, `--font-body: 'Inter'`, etc.
2.  **Style `ChatbotButton`**: Style the floating button with a neon glow effect on hover.
3.  **Style `ChatWindow`**: Style the main panel with rounded corners, circuit-line borders, and the AI-mesh background. Implement the dark mode look.
4.  **Style `ChatMessage`**: Create distinct styles for user messages and bot messages.
5.  **Add Animations**: Implement CSS transitions for the smooth open/close animation of the `ChatWindow`.

### Phase 4: State Management & Interaction Logic

**Goal**: Bring the UI to life with client-side state and event handling.

1.  **Manage State**: In the main `index.tsx` container, use `useState` to manage `isOpen`, `messages`, and `isThinking` as defined in `data-model.md`.
2.  **Button Handler**: Wire the `onClick` handler for `ChatbotButton` to toggle the `isOpen` state.
3.  **Message Sending**:
    -   Implement the `handleSend` function that adds a new user message to the `messages` array.
    -   After sending, use `setTimeout` to simulate a bot reply: set `isThinking` to true, then after a delay, set it to false and add a placeholder bot message to the array.
4.  **Auto-scrolling**: Use a `ref` on the message container and the `useEffect` hook to scroll to the bottom whenever the `messages` array changes.
5.  **Enter Key**: Add a `onKeyDown` handler to the input in `ChatInput.tsx` to trigger sending when the Enter key is pressed.

### Phase 5: Docusaurus Integration

**Goal**: Ensure the chatbot is loaded on every page.

1.  **Use Docusaurus `Root` Wrapper**: Docusaurus provides a `src/theme/Root.tsx` file that can be "swizzled" (overridden) to wrap the entire application.
    -   Run `npm run swizzle @docusaurus/theme-classic Root -- --danger` to create the file.
    -   In the new `src/theme/Root.tsx`, import the `Chatbot` container from `src/components/chatbot` and render it alongside the original `{children}`.
2.  **Verify Global Availability**: Start the dev server and navigate between different pages to ensure the chatbot button is always present.
3.  **Check for Conflicts**: Inspect the browser console for errors and visually check for any layout or style conflicts with the existing Docusaurus theme.

### Phase 6: Documentation

**Goal**: Document the component for future use and maintenance.

1.  **Create `README.md`**: Inside `docusaurus-book-site/src/components/chatbot/`, create a `README.md` file.
2.  **Add Content**:
    -   Explain the purpose of the chatbot component.
    -   Describe the component hierarchy.
    -   Explain the state management strategy.
    -   Provide instructions on how to adjust the theme via `chatbot.module.css`.
    -   Clearly mark the placeholder `setTimeout` function as the location for future backend API integration.
