# Implementation Plan: Chatbot Frontend Logic & UX Enhancements

**Branch**: `005-chatbot-frontend-logic` | **Date**: 2025-12-01 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/005-chatbot-frontend-logic/spec.md`

## Summary

This plan outlines the transformation of the existing Docusaurus chatbot UI shell into a fully interactive and user-friendly frontend. The technical approach involves refactoring existing components, implementing robust client-side state management using `Zustand`, rendering rich Markdown content using `react-markdown`, and enhancing user experience through improved input controls, visual feedback, and a robotics-aligned theme. Mocked assistant responses will be used, with no backend integration in this feature.

## Technical Context

**Language/Version**: TypeScript (React 18)
**Primary Dependencies**: React, Docusaurus, Zustand, react-markdown, remark-gfm, react-syntax-highlighter
**State Management**: Zustand (centralized store for chat state)
**Styling**: CSS Modules (`.module.css`), native CSS variables
**Animation**: CSS Transitions
**Testing**: Manual testing based on user scenarios in `spec.md`.
**Target Platform**: Web (Desktop, Tablet, Mobile)
**Project Type**: Web Application (Docusaurus)
**Constraints**: Must not interfere with existing Docusaurus theme. Must be globally available on all pages. Frontend-only, no backend integration. In-memory chat history only.

## Phased Implementation Plan

### Phase 1: Refactoring & Dependency Setup

**Goal**: Prepare the environment and restructure the existing chatbot components.

1.  **Install Dependencies**: Add `zustand`, `react-markdown`, `remark-gfm`, `react-syntax-highlighter` to `docusaurus-book-site/package.json`.
2.  **Refactor `Chatbot/index.tsx`**: Rename/restructure the current `index.tsx` content to become the new `ChatContainer.tsx`.
3.  **Update `Chatbot/index.tsx`**: Make the main `index.tsx` a simple re-export of `ChatContainer` or handle global state provider setup if necessary.
4.  **Create `hooks/useChatStore.ts`**: Define the Zustand store with `Message` and `ChatState` structure, and corresponding actions.

### Phase 2: State Management & Message Rendering

**Goal**: Implement the core chat state logic and display messages with Markdown support.

1.  **Integrate Zustand into `ChatContainer.tsx`**: Replace local `useState` calls with `useChatStore`.
2.  **Create `MessageBubble.tsx`**: Component to render a single `Message` object using `react-markdown` and `react-syntax-highlighter`. Apply distinct user/assistant styles.
3.  **Create `MessageList.tsx`**: Component to display the `messages` array, managing auto-scroll to the latest message.
4.  **Update `ChatWindow.tsx`**: Replace its `children` prop with direct rendering of `MessageList`.

### Phase 3: Input Enhancements & Mock Logic

**Goal**: Implement an enhanced input experience and integrate the mock assistant response.

1.  **Refactor `ChatInput.tsx`**:
    -   Update to support multi-line input (e.g., using a `<textarea>`).
    -   Implement `Enter` to send, `Shift+Enter` for new line logic.
    -   Integrate with `useChatStore` to disable input when `isLoading` is true.
2.  **Create `LoadingIndicator.tsx`**: A small component to visually indicate the assistant is "typing".
3.  **Implement Mock Assistant**:
    -   Create a utility function or integrate directly into `ChatContainer.tsx` to simulate a delayed (500-900ms) placeholder assistant response, updating the store.
    -   Integrate with `isLoading` state.

### Phase 4: UI Features & Polish

**Goal**: Implement empty/error states, context selection, and refine UX/UI.

1.  **Implement Empty/Error States**:
    -   In `MessageList.tsx`, display "No messages yet — start chatting" when `messages` is empty.
    -   Display mock error messages (`error` state from store) in a prominent but non-intrusive way.
2.  **Add Reset Chat Functionality**:
    -   Implement a "Reset Chat" button (e.g., in `ChatWindow` header or `ChatContainer`).
    -   Wire it to the `resetChat` action in `useChatStore`.
3.  **Create `ContextModeSelector.tsx`**: Implement the dropdown/toggle for "Ask full book" / "Ask selected text only" (prototype with placeholder preview area for selected text).
4.  **Integrate `ContextModeSelector.tsx`**: Place it in `ChatWindow` header or `ChatContainer`.
5.  **Animations & Theming**:
    -   Implement fade-in animations for new messages.
    -   Review and refine all component styles (deep blue, silver, neon cyan accents) for consistency with the robotics theme and Docusaurus dark mode.
    -   Ensure smooth auto-scroll.

### Phase 5: Testing & Documentation

**Goal**: Validate functionality and update documentation.

1.  **Manual Verification**: Thoroughly test all user scenarios from `spec.md` and acceptance criteria.
2.  **Update `README.md`**: Update `docusaurus-book-site/src/components/chatbot/README.md` with the new component hierarchy, Zustand store usage, Markdown rendering details, and context mode.
3.  **Cleanup**: Remove any temporary code or comments.
